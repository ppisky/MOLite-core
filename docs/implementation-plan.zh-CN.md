# MOLite Core 实施记录

按完整产品范围实施，阶段完成后运行对应验证并本地 Git 提交。不推送或发布。MOMO 参考版本：`b01ec5e8744b0c549bb041ab22c31ba89f60d3a4`。

1. 基线：保存已有设计、持久化提炼调度及测试。已提交 `e499e9b`。
2. 持久化领域层：服务商、模型、模型参数组、用途选择；角色、场景、会话、标签、数据资源；版本化消息及事件。
3. DMW / MO State：来源索引、检索、五维状态、快照、生命周期、修改失效与修复；调度和记忆结果原子提交。
4. 模型与运行时：三种上游协议、图片直传/视觉回退、对话与提炼、失败恢复和取消。
5. MOC：复用原生容器、加密实现；多角色、会话、记忆及可选数据文件导入导出，校验及冲突处理。
6. 接入：共用 Rust 操作接口、HTTP / SSE、标准 C ABI；头文件、示例与集成验证。
7. 验收：运行全套测试、格式和 Clippy；更新使用说明、实现状态及限制，提交最终记录。

每阶段记录实际实现与验证结果；未实现能力不标为完成。模型联调默认使用本地模拟服务，不使用付费凭据。关键验收包括提前提炼重置周期、失败冻结证据、场景隔离、编辑删除修复、图片能力路由、MOC 往返与 C 内存释放。

产品主链路已接通，不能把以下兼容目标标为完成：旧MOMO Space会话/DMW文件树自动迁移；供应商专用token预算器；可编辑YAML状态契约；Linux/macOS实机ABI验证。PDF解析也未包含，但PDF存储、读取和随MOC携带已经实现。上述边界同步写入README，不以空壳接口冒充能力。

MOLite原生运行数据选择显式MOC扩展，与原版角色模块共存，未更改原生manifest含义。实际接口以docs/api.zh-CN.md、docs/c-abi.zh-CN.md及include/molite.h为准。所有Git提交仅在D:/MOLite-core，本次未改动或推送MOMO参考仓库。

最终验收：cargo fmt --check、cargo test --locked（30项）、cargo clippy --locked --all-targets -- -D warnings、cargo build --release --locked、真实C调用脚本与git diff --check均通过。Release DLL为9,791,488字节，HTTP程序为11,137,536字节；这是构建大小，不是延迟或吞吐量基准。
