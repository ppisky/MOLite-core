MOLite Core

从 MOMO Core 收敛 · 当前设计共识
轻量 · 快速 · 配置简单 · 尚未实现
保留核心运行能力
  • MO State v2状态、叙事情境、快照、恢复
  • DMW 长期记忆检索、自动提炼、生命周期维护
  • 每 12 个完整问答自动提炼保留现有节奏，不改成用户手动
调整记忆范围与分类
  • 记忆只向指定场景范围注入
  • 需要延续记忆时，自己切换范围
  • 没有角色级记忆池或自动共享
  • 文件夹、标签负责分类分类不改变记忆注入范围
保留原生 MOC 与数据文件
  • 只使用原生 MOC沿用角色、会话、记忆等携带能力
  • TXT、PNG、PDF 等独立存储
  • 数据文件通常随 MOC 携带也可以明确选择不携带
  • 原版加密能力保留
明确消息修改后的记忆修复
  • 消息与派生记忆保留强来源索引
  • 编辑、重生、删除后重新提炼定位受影响记录，撤下失效记忆
  • 通知使用者处理状态与结果来源修复不等下一批 12 轮
移除不进入 MOLite 的部分
  • 个人空间体系
  • NSG 与 Turso 向量存储
  • LSB 与图片载体
  • 外部角色卡格式兼容普通 PNG 附件仍然支持
明确模型配置与请求
  • 先配置基础服务商地址、凭据、文本模型与视觉模型
  • 再建立模型参数组选择模型、请求方式、具体请求参数
  • 三个用途分别选择组
    对话记忆视觉回退
  • 对话模型能看图 → 直接看原图只能读文本 → 视觉回退描述后再对话
  • 保留三种模型接口Chat Completions · Responses · Anthropic Messages
新增C ABI，形成三种接入
  • Rust API 与 HTTP 保留
  • 新增标准 C ABI
  • 三种入口共用同一套 Core
    Rust APIHTTPC ABI
待细化工程契约与术语
  • 场景、会话的最终命名与映射已经理解区别，尚未强制统一命名
  • 存储布局、MOC 数据映射
  • 文件限额、上下文预算
  • 接口契约、平台和性能指标
